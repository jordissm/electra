# Rivet analysis

Rivet plugins are in `rivet-analyses/electra/` and `rivet-analyses/pdg/`.
Build them in an environment providing Rivet and its dependencies:

```bash
cd rivet-analyses
bash build-analyses.sh electra
```

The build script emits one library per source file under `build/electra/`.
A second argument selects the output root. Run it with `pdg` to build the
additional PDG analyses.

The transverse-momentum runner accepts a SMASH event tree, aggregated eHIJING
metadata and the corresponding library. From the repository root:

```bash
bash rivet-analyses/rivet_analysis_dndptdz_submit.sh \
  /path/to/run/smash/events \
  /path/to/run/ehijing/DISKinematics.meta.jsonl \
  /path/to/rivet-analyses/build/electra/Rivet_EHIJING_SMASH_2026_DNDPTDZ.so \
  0.0 1.1 11
```

The final arguments are the minimum, maximum and number of transverse-momentum
bins. Select them for your analysis. Despite its filename, this runner invokes
Rivet directly; it is distinct from `slurm-scripts/analysis_submit.sh`.
It targets Rivet 3.1.7 and uses environment variables for configuration.
Output YODA files remain separate by SMASH profile rather than being merged
across profiles. Inspect the other runners for their kinematic arguments.

The aggregated metadata is generated by the eHIJING SLURM postprocessing job.
For local runs, prepare that aggregate from the matching per-event metadata
before invoking a runner. Retain the physical event ID associations.
